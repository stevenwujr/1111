# OpenSpec Workflow

This folder contains an OpenSpec-style project workflow for DIC3. The structure follows a spec-driven process that starts with the problem and ends with implementation-ready requirements and evidence of acceptability.

## Workflow philosophy

The workflow is intentionally simple:

1. define the decision problem
2. specify the project abstraction
3. capture the core system capabilities
4. state constraints and trade-offs
5. document operational workflow and success criteria

## Primary documents

- `project-abstraction.md` — A–F abstraction and project framing
- `core-capabilities.md` — 5 core capabilities
- `trade-offs.md` — 3 design trade-offs
- `details.md` — 10 detailed design notes
- `workflow.md` — operational workflow translated from `design.md`
