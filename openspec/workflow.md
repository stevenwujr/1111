# OpenSpec Workflow

## Ingest
- define the project problem statement
- identify stakeholders and decision contexts
- specify constraints, risks, and success criteria

## Frame
- establish the A-F abstraction
- define the project aim, background, and target environment
- identify core capabilities and design constraints

## Model
- create a context-aware evidence layer
- structure the recommendation pipeline
- define collaboration and review roles

## Verify
- validate recommendation quality and uncertainty calibration
- test explanation quality and user trust
- run scenario-based and operational evaluations

## Deploy
- ship a monitored decision-support workflow
- enable human review and override
- capture feedback for continual learning and governance

## Iterate
- update the system based on outcomes, drift, and stakeholder feedback
- revise requirements when the operational context changes
- keep the proposal aligned with the evolving design reality
